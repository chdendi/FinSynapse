# 供应链扫描方法论 (Supply Chain Methodology)

> 适用：所有遵循 `templates/industry-report.md` 的行业/产业链研究报告。
> 版本：0.1（参考 serenity-skill 瓶颈狩猎体系）
> 核心思路：将宽泛的市场主题转化为"系统变化 → 稀缺环节 → 上市公司"的可操作研究管道

---

## 1. 研究管道概览

```
市场主题 → 系统变化 → 必需部件 → 供应链层级 → 稀缺约束 → 上市公司 → 证据 → 市场认知偏差 → 可证伪条件
```

行业报告的核心产出不是"这个行业有多少家公司"，而是"在什么环节、哪几家公司最值得优先研究、为什么、什么情况下这个判断是错的"。

---

## 2. 定范围 (Scope)

对每次扫描，先明确：

| 维度 | 内容 | 示例 |
|------|------|------|
| **市场** | A 股 / 港股 / 美股 / 台 / 日 / 韩 / 欧 / 全球 | A 股 |
| **主题** | AI 半导体 / 先进封装 / 机器人 / 光电共封装 (CPO) / 新能源 / 医疗器械 | AI 半导体全产业链 |
| **时间窗** | 默认 3-12 个月研究窗口 | 2026 H2-2027 |
| **产出** | 优先级研究名单 + 推理链 + 下一步验证清单 | Top 5 标的 + 降级说明 |

只在意缺失会**实质改变结论**的 scope 时才向用户追问；其他缺失可合理推定的由 agent 自行推定。

---

## 3. 画产业链地图 (Value-Chain Map)

### 3.1 8 层架构模板

把主题转成可操作的产业链地图，从下游到上游逐层展开：

```
[第1层] 终端客户与资本支出源
  ├── 谁在花钱？capex 来自哪里？
  └── 例：云厂商 AI CapEx、国家智算中心、电网投资

[第2层] 系统集成商与 OEM
  ├── 谁把部件整合成交付系统？
  └── 例：AI 服务器厂商、光通信系统商、机器人整机厂

[第3层] 模块与子系统
  ├── 系统里的关键功能模块是什么？
  └── 例：光模块、交换机、液冷系统、执行器模组

[第4层] 芯片、器件与核心元件
  ├── 模块里的核心芯片/器件？
  └── 例：GPU/CPU/FPGA/ASIC、DSP、激光器、传感器

[第5层] 制程、封装与测试
  ├── 谁制造这些芯片？怎么封？
  └── 例：晶圆代工、先进封装 (CoWoS/XDFOI)、CP 测试

[第6层] 设备与量测
  ├── 制造和封装需要什么设备？
  └── 例：刻蚀机、薄膜沉积、检测设备、键合设备

[第7层] 材料、耗材与特种输入
  ├── 设备和制程消耗什么？
  └── 例：硅片、光刻胶、电子特气、封装基板

[第8层] 物理基础设施
  └── 例：电力、冷却、厂房、纯水/化学品供应
```

### 3.2 建图规则

- 每层至少 3 家可识别的公司（上市或未上市）
- 未上市公司也要列出并标注 `（未上市）`，因为它们是价值链的关键环节
- 有明显差异化经济特征的种类**不应合并**到一个笼统的"零部件"层
- 最终候选池应达 **≥20 家**（市场足够大时）

## 4. 找稀缺层 (Scarce Layer Hunt)

### 4.1 判定信号（6 个维度）

当以下信号叠加出现时，该产业链层级可能构成稀缺/瓶颈：

| # | 信号 | 含义 | 查验方式 |
|---|------|------|---------|
| 1 | **不可替代性** | 客户不经过它就无法扩张 | 技术路线图分析、客户 capex 分解 |
| 2 | **供应商数量少** | 全球/国内 ≤5 家合格供应商 | 行业协会、客户供应商名单 |
| 3 | **认证/验证慢** | 新进入者需要 ≥18 个月才能通过客户认证 | 客户验厂公告、供应商准入流程 |
| 4 | **扩产有物理约束** | 需要专用设备、专业许可、高纯度材料或特殊工艺 | 环评/能评、设备交货周期、人才供给 |
| 5 | **客户紧迫度** | 预付款、产能预留、长协、加急订单 | 合同负债、预收款、产能利用率 |
| 6 | **市场认知滞后** | 公开市场仍按旧业务分类看待该公司 | 券商覆盖报告分类、指数分类 |

### 4.2 稀缺度分级

| Tier | 含义 | 标准 |
|------|------|------|
| **Tier 1 致命瓶颈** | 缺失则整个产业停滞 | 不可替代性最高 + 供应商极少 + 替代周期 ≥5 年 |
| **Tier 2 严重受限** | 明显制约产业发展速度 | 国产化率 ≤20% + 良率/产能差距显著 |
| **Tier 3 快速追赶** | 有差距但收敛快 | 已进入量产/验证 + 差距 ≤1 代 |

### 4.3 先排层级再排公司

在给具体标的排序之前，**先给产业链层级排序**。这是 serenity-skill 方法论的核心纪律：

```text
先排产业链层级：设备平台、关键工艺设备、算力芯片、先进封装材料、普通零部件。
前两层更接近晶圆厂扩产的硬约束，后面几层需要更强的订单证据才能往前排。
```

示例输出格式：

| 优先级 | 产业链层级 | 稀缺理由 | 代表标的数 |
|:------:|-----------|---------|:--------:|
| 1 | 半导体设备 | 晶圆厂扩产必经之路，国产化率低 | 3 |
| 2 | 先进制程代工 | 国内唯一供应源，无替代 | 1 |
| ... | ... | ... | ... |

## 5. 建候选池 (Company Universe)

### 5.1 覆盖广度要求

- 初始候选池 ≥20 家（市场有足够上市公司时）
- 跨以下类别全面覆盖：
  - 明显龙头 + 国产替代概念
  - 上游设备（平台型 + 工艺专用型）
  - EDA / IP / 设计基础设施
  - 关键材料与耗材
  - 检测与量测
  - 先进封装 / OSAT
  - 基础设施与电力
  - 热门但需降级的标的

### 5.2 标的分类标注

每个候选标注其在价值链中的位置：

| 分类 | 含义 | 排序权重 |
|------|------|:------:|
| **控制稀缺层** | 直接掌握瓶颈环节定价权 | 最高 |
| **供应稀缺层** | 向瓶颈层提供不可替代输入 | 高 |
| **受益于需求** | 需求拉动但无瓶颈控制力 | 中 |
| **有曝光但议价力弱** | 主题相关但定价权有限 | 低 |
| **故事好但证据弱** | 叙事强但缺乏可验证来源 | 不推荐 |

## 6. 收证据 (Evidence Gathering)

### 6.1 来源优先级

按 [`evidence-ladder.md`](./evidence-ladder.md) 三级体系：

- **强证据优先**：年报/季报/公告/交易所披露/招股书/监管批文/专利/认证记录
- **中等证据辅助**：主流财经媒体/行业协会/咨询机构/券商研报（假设可见时）
- **弱证据仅作线索**：KOL/社交/论坛/无出处截图 — 不能独立支撑排名

### 6.2 全量扫描标准

对于当前主题扫描，在工具和运行时间允许时目标：
- 10+ 公告/年报/季报/交易所文件
- 5+ 公司 IR/路演/产品/技术来源
- 5+ 可信媒体/行业协会/专利/标准/项目记录
- 额外来源用于交叉验证估值、流动性与融资

### 6.3 A 股专项核查路径

对中国 A 股标的，特别核查：
- 年报、半年报、季报、临时公告
- 交易所问询函、互动易、上证 e 互动
- 招投标、中标公告、客户认证记录
- 环评/能评、地方项目备案、产能建设进度
- 专利、标准、行业协会资料
- 应收、存货、合同负债、现金流、毛利率
- 关联交易、资产注入、定增、可转债、股权质押

## 7. 排标的 (Rank Candidates)

### 7.1 8 维排序框架

| # | 维度 | 说明 |
|---|------|------|
| 1 | **需求压力** | 下游需求的确定性与紧迫度 |
| 2 | **稀缺度** | 供应商数量、认证壁垒、替代周期 |
| 3 | **供应商集中度** | 合格供应商 ≤3 家 vs ≥10 家 |
| 4 | **扩产难度** | 需要多少时间/资本/许可/人才扩产 |
| 5 | **证据强度** | 支持该位置的数据质量（强/中/弱分布） |
| 6 | **估值与市场认知** | 市场是否已充分定价 / 存在认知偏差 |
| 7 | **近期催化剂** | 未来 3-6 个月是否有可观察事件驱动重估 |
| 8 | **风险折让** | 融资/治理/流动性/地缘/会计/周期等减分项 |

### 7.2 评分工具

当需要可复现的数值评分时，使用 [`scoring-methodology.md`](./scoring-methodology.md) 的加权评分框架。

### 7.3 每个最终标的必答

对每一个入选 Top N 的标的，报告中必须回答：

1. 它卡住的是什么环节？（精确到具体工艺/产品/规格）
2. 它在产业链的哪一层？
3. 为什么排在当前这个位置？（不是更低也不是更高）
4. 支撑这个排名的证据是什么？
5. 什么情况下这个排名会下降？

## 8. 解释答案 (Explain the Answer)

### 8.1 答案结构模式

从结论开始，逐步展开推理：

```
① 值得优先看的产业链层级
② 各层的 Top 标的
③ 为什么这些标的排在这里
④ 最强证据
⑤ 被降级的热门方向（至少 1 个）及原因
⑥ 这个判断最容易错在什么条件
⑦ 下一步验证清单
```

### 8.2 语言风格

- 用研究对话的语气，不用 broker report 语气
- 中文优先使用："产业链卡点"、"市场可能没看清的地方"、"什么情况说明这个判断错了"
- 避免："强烈推荐"、"目标价"、"买入评级"
- 可以做强判断（"这个排前面是因为它更靠近真实扩产约束"），但必须跟证据

### 8.3 热门方向降级

**每个行业扫描报告必须至少降级 1 个热门方向**，并说明原因。这是防止"羊群效应"的自检机制。

示例：
> 这个热门方向我会先降级，因为它虽然叙事热，但：
> 1. 供应商数量超过 20 家，不构成稀缺
> 2. 下游客户无紧迫信号（无预付款/长协）
> 3. 毛利率持续下行，说明无定价权

## 9. 完整性最低标准

每次主题扫描在产出最终报告前，尽量满足：

| 标准 | 要求 |
|------|------|
| 产业链层级覆盖 | ≥3 层 |
| 来源数量 | ≥25（工具和运行时间允许时） |
| 候选池 | ≥20 家（市场足够大时） |
| 最终优先级标的 | 3-7 家 |
| 降级热门方向 | ≥1 个 |
| 每个 Top 标的证据 | ≥2 条强/中证据 |
| 判断易错条件 | 每个 Top 标的 ≥1 条 |
| 下一步验证清单 | ≥3 条具体动作 |

若工具或时间无法达标，在 `## Meta` 中说明限制，并给出聚焦的部分答案 + 明确的验证路径。
